## Tech stack

- NestJS 11 (TypeScript)
- TypeORM 0.3 + PostgreSQL (`pg`)
- `class-validator` / `class-transformer` for request validation

## Prerequisites

- Node.js 20 or newer
- PostgreSQL 13 or newer running on your machine

## 1. Database setup

Create an empty database:

```bash
createdb -h localhost -p 5432 -U postgres product_management
```

Or from psql:

```sql
CREATE DATABASE product_management;
```

The `products` and `employees` tables are created automatically on the first
start because `DB_SYNCHRONIZE=true` is set in `.env.example`.

## 2. Environment

```bash
cp .env.example .env
```

Then edit `.env` and put your own PostgreSQL user and password in `DB_USER` and
`DB_PASSWORD`. The real `.env` is git-ignored and is not part of this submission.

## 3. Install and run

```bash
npm install
npm run start:dev
```

The API listens on `http://localhost:3000`. You should see all ten routes
printed in the startup log, e.g. `Mapped {/products, POST} route`.

Production build:

```bash
npm run build
npm run start:prod
```

## 4. Endpoints

### Products

| Method | Endpoint | Behaviour | Status |
| --- | --- | --- | --- |
| POST | `/products` | Create and save a product | 201 |
| GET | `/products` | Return all products | 200 |
| GET | `/products/:id` | Return one product | 200, 404 if unknown |
| PATCH | `/products/:id` | Update the given fields | 200, 404 if unknown |
| DELETE | `/products/:id` | Delete the product | 200, 404 if unknown |

Product fields: `id` (generated by PostgreSQL), `name`, `category`, `price`,
`quantity`.

### Employees

| Method | Endpoint | Behaviour | Status |
| --- | --- | --- | --- |
| POST | `/employees` | Create and save an employee | 201 |
| GET | `/employees` | Return all employees | 200 |
| GET | `/employees/:id` | Return one employee | 200, 404 if unknown |
| PATCH | `/employees/:id` | Update the given fields | 200, 404 if unknown |
| DELETE | `/employees/:id` | Delete the employee | 200, 404 if unknown |

Employee fields: `id` (generated by PostgreSQL), `name`, `email`, `phone`,
`password`, `age`, `yearsOfWorking`.

`password` is a dummy field. It is stored in the database but read back with
`select: false`, so no endpoint returns it.

## 5. Example requests

```bash
# create
curl -X POST http://localhost:3000/products \
  -H "Content-Type: application/json" \
  -d '{"name":"Rice Bag 5kg","category":"Grocery","price":12.5,"quantity":40}'

# all
curl http://localhost:3000/products

# one
curl http://localhost:3000/products/1

# update
curl -X PATCH http://localhost:3000/products/1 \
  -H "Content-Type: application/json" -d '{"price":14.75,"quantity":33}'

# delete
curl -X DELETE http://localhost:3000/products/1
```

## 6. Project structure

```
src/
  main.ts                        # bootstrap + global ValidationPipe
  app.module.ts                  # ConfigModule + TypeOrmModule.forRootAsync
  config/database.config.ts      # Postgres options + snake_case naming strategy
  modules/
    product/
      entities/product.entity.ts
      dto/create-product.dto.ts
      dto/update-product.dto.ts
      product.controller.ts      # HTTP layer only
      product.service.ts         # all database access lives here
      product.module.ts
    employee/
      entities/employee.entity.ts
      dto/create-employee.dto.ts
      dto/update-employee.dto.ts
      employee.controller.ts
      employee.service.ts
      employee.module.ts
```

Table and column names follow the class naming convention: `Product` →
`products`, `yearsOfWorking` → `years_of_working`.
